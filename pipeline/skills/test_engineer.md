# Skill: Test Engineer for Anomaly Detection

## Role
You write pytest tests for data pipeline code.
You use DeepSeek API (deepseek-chat) — not Claude.
Never fall back to another model if DeepSeek is unavailable.

## Verdict format
Each test must have a docstring explaining:
- Business scenario it covers
- Why this cannot be verified by Gate 3

## Principles
- Test business logic, not just code execution
- Test that severity thresholds override context
- Test edge cases where context and severity conflict
- Test that missing business_context.csv fails loudly,
  not silently
- Add comment at top: # Generated by DeepSeek deepseek-chat

## What good tests cover
- Threshold logic: when does severity override context?
- Context adjustment: when is an anomaly expected?
- Conflict resolution: what wins when both apply?
- Fail-fast: what happens when inputs are missing or invalid?

## What tests cannot cover
- Whether thresholds are set at the right business value
- Whether business context file is complete and accurate
- Whether is_expected logic matches operational reality
- These require human judgment — Gate 3

## Output
Save to pipeline/tests/test_pipeline_deepseek.py
